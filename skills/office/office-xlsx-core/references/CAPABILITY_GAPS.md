# excel-master 能力缺口

> v1.0 已知边界。当用户需求落入以下领域时，**不盲做**——先告知这是已知缺口，触发需求讨论。

---

## Tier 3 — 需独立 skill 的复杂场景

以下场景不在 `office-xlsx-core` 覆盖范围内。遇到时，Agent 应：
1. **告知用户**「这超出我当前能力范围，属于已知缺口」
2. **不硬做**——不要尝试用 openpyxl 手写一个透视表引擎
3. **触发讨论**——问用户「要不要现在设计这个 skill？」

| # | 缺口 | 为什么不在 v1 | 触发条件示例 |
|---|------|-------------|-------------|
| 1 | **数据透视表 + 切片器** | 复杂业务逻辑（行/列/值/筛选器设计），不是一两条 CLI 命令 | "建一个透视表，行是地区，列是月份" |
| 2 | **公式审计/依赖分析** | 需要构建依赖图、跨 sheet 追踪、大量计算 | "找出所有 #REF! 的根源公式" |
| 3 | **raw XML 操作** | 需要理解 OOXML 结构，万能但学习曲线高 | "直接改 xl/styles.xml 的默认字体" |
| 4 | **多工作簿合并/外部引用** | 跨文件 VLOOKUP 追踪、多源数据聚合 | "把这 5 个 xlsx 汇总到一个文件" |
| 5 | **openpyxl 深度操作** | 块探测、列映射、公式生成——Python 密集型 | "检测 sheet 里的数据块并自动映射列" |

## 非 xlsx 格式

| 格式 | 策略 |
|------|------|
| `.docx` / `.pptx` | 直接返回 REJECTED，不尝试处理 |
| `.csv` / `.tsv` | 可以用 `officecli import` 转 xlsx 后处理（属于 v1 能力） |
| `.xls` (旧格式) | 不支持，告知用户需先转为 .xlsx |
| `.xlsm` (宏) | 可读取数据，但宏/VBA 不处理 |

## 非功能需求

| 缺口 | 说明 |
|------|------|
| 超大型文件（>200MB） | 未测试。dump→batch 策略可能仍有效，但内存边界未知 |
| 并发安全 | 同一文件被多个 Agent 同时操作的行为未定义 |
| 渲染保真度 | `view screenshot` 生成的效果与 Excel/WPS 实际打开可能存在差异 |
